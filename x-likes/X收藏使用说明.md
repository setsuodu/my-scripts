# X 收藏使用说明

把 X（Twitter）上看到的贴文，一键存成 Obsidian 笔记，图片和视频一起存到本地。

> 写于 2026-10-21。脚本版本：`x-save-json.user.js` v1.2.0，`x_ingest.py` 初版。
> 这套东西是边聊边写的，我没有长期跑过。第一次用时留意输出，出问题先看最后的「故障排查」。

## 1. 整体流程

```
X 贴文详情页
   │  油猴脚本（面板上点"保存为 JSON"）
   ▼
浏览器下载文件夹：x_作者_贴文ID.json
   │  x_ingest.py（要先运行起来，会自动监视下载文件夹）
   ▼
D:\GitLab\obsidian-x\
   ├─ 2026\                  ← 当年所有 md
   │   ├─ 2026-10-21_xxx_贴文ID.md
   │   └─ media\             ← 当年所有图片、视频，平铺
   │       ├─ 贴文ID_i1.jpg
   │       └─ 贴文ID_v1.mp4
   └─ _raw\2026\             ← 原始 JSON 归档（事实来源，可重新生成 md）
```

**原则**：JSON 是原始数据；md 和媒体文件都是衍生品，丢了可以从 `_raw` 重建。

## 2. 第一次安装

### 2.1 油猴脚本

1. 浏览器装 Tampermonkey。
2. 新建脚本，把 `x-save-json.user.js` 的内容整个粘进去保存。
3. **更新脚本后，已经打开的 X 页面必须刷新一次**，否则脚本抓不到视频地址。

### 2.2 入库程序

1. 装 Python 3.8 或更高版本。只用标准库，不用装任何依赖。
2. 把 `x_ingest.py` 放在固定位置（建议 `D:\GitLab\obsidian-x\_tools\`）。
3. 检查脚本顶部的配置：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `VAULT` | `D:\GitLab\obsidian-x` | 笔记仓库位置 |
| `INBOX` | 用户目录下的 `Downloads` | 浏览器下载文件夹，不是这个就改，或者运行时用 `--inbox` |
| `YEAR_BY` | `"posted"` | `posted` 按贴文发布年份归档；`saved` 按保存年份 |
| `POLL_SECONDS` | `2` | 监视下载文件夹的间隔（秒） |

## 3. 日常使用

1. 运行入库程序，保持窗口开着：
   ```
   python x_ingest.py
   ```
2. 在 X 上打开某条贴文的**详情页**（地址是 `x.com/用户名/status/数字`）。右下角会出现面板。
3. 面板上选好后，点「保存为 JSON」：

| 控件 | 说明 |
|---|---|
| 分类 | 默认、AI、开发、设计、其它。记住上次的选择，写进 md 的 `category` |
| 同时保存引用贴文 | 默认勾选。引用贴文的内容会单独保存，不会和主贴混在一起 |
| 保存后取消喜欢 | 默认不勾。勾选后保存完会点一次"取消喜欢"并显示结果 |

4. 面板提示"已保存"后，几秒内入库程序窗口会打印一行处理结果，Obsidian 里就能看到新笔记。

**取消喜欢的使用习惯**：一次只处理一条，手动点。不要写自动循环批量取消喜欢，连续的写操作有触发风控的风险。

## 4. 入库程序的命令

```
python x_ingest.py                      # 常驻，监视下载文件夹
python x_ingest.py --once               # 处理一次就退出
python x_ingest.py --rebuild            # 重新处理 _raw 里的 JSON：补下载缺失的媒体，补生成缺失的 md
python x_ingest.py --rebuild --force    # 连已有的 md 也覆盖（手改过的笔记会丢）
python x_ingest.py --inbox "E:\下载"    # 指定下载文件夹
python x_ingest.py --vault "D:\其它路径" # 指定笔记仓库
```

**md 的覆盖规则**：已经存在的 md 不会被覆盖，因为里面可能有你手写的笔记。唯一的例外：上次因为缺视频地址在 md 里带了"未下载"警告，这次重新保存后补齐了，才会自动重新生成。

## 5. 生成的 md 长什么样

- **文件名**：`2026-10-21_作者handle_贴文ID.md`，日期开头方便排序，ID 保证唯一。
- **媒体文件名**：`贴文ID_i1.jpg`（图片）、`贴文ID_v1.mp4`（视频）；引用贴文的多一个 `q`，如 `贴文ID_qv1.mp4`。所有媒体平铺在一个文件夹，所以文件名必须带 ID。
- **frontmatter**：`url`、`tweet_id`（字符串）、`author`、`handle`、`posted`、`saved`、`category`、`tags`。
- **正文**：原文；X 自动翻译的译文放在一个 `note` 提示块里；然后是 `![[媒体文件名]]` 内嵌；引用贴文放在 `quote` 提示块里；最后是"在 X 打开"的链接。
- 媒体下载失败或缺视频地址时，末尾会有一个 `warning` 提示块，列出问题。

## 6. JSON 里有哪些字段

`category`、`url`、`id`、`author`（`name` 和 `id`）、`time`（UTC）、`time_local`、`text`（页面上看到的文字，开了自动翻译就是译文）、`text_original`（接口里的原文）、`lang`、`images`、`videos`（页面上的 blob 地址，只在当前标签页有效，没用）、`media`（接口里的图片原图、视频各码率 mp4 和 m3u8，`best_mp4` 是最高码率）、`video_network_urls`（兜底，经常是空的）、`saved_at`、`quoted`（引用贴文）。

注意：贴文 ID 超过 JS 的安全整数范围，所有地方都要当**字符串**处理。

## 7. 故障排查

| 现象 | 可能原因和处理 |
|---|---|
| 右下角没有面板 | 不在详情页（地址要有 `/status/数字`）；或脚本没启用。刷新页面 |
| 提示"没找到主贴" | 页面还没加载完，等一下再点 |
| 提示"没捕获到视频的 mp4 地址" | 装脚本后没刷新页面。**刷新本页再保存**。此时取消喜欢会被自动跳过 |
| JSON 一直留在下载文件夹 | 入库程序没运行；或下载文件夹不对，用 `--inbox` 指定；或浏览器开了"每次询问保存位置" |
| md 里有"未下载"警告 | 网络失败或没有 mp4。重新保存一次，或运行 `--rebuild` 重试 |
| 命令行里中文乱码 | 只影响显示，不影响文件内容 |
| 同一条贴文保存了两次 | 原始 JSON 会被新的覆盖，已有 md 不会重复生成 |

## 8. 已知限制

- **只有 m3u8 没有 mp4 的视频不会下载**。md 里会有警告，原始 JSON 保留着，以后可以用 ffmpeg 或 yt-dlp 补。
- **引用贴文的 url 不一定能拿到**，要靠接口数据，拿不到就只有作者、时间、正文和媒体。
- **取消喜欢是模拟点击页面按钮**，不是调接口，所以依赖 X 的页面结构。
- **长贴文、翻译等字段来自 X 的内部接口**，字段名可能随 X 改版变化。

## 9. 坏了怎么修（X 改版时）

油猴脚本依赖两类东西，X 改版后可能失效：

1. **接口字段**（用来取 mp4、原文、引用 ID）：`rest_id`、`legacy.full_text`、`legacy.extended_entities.media`、`video_info.variants`、`note_tweet`、`quoted_status_id_str`。症状：JSON 里 `media` 为空，或 `text_original` 为空。
2. **页面选择器**（用来取作者、时间、取消喜欢）：`data-testid` 为 `tweet`、`User-Name`、`tweetText`、`tweetPhoto`、`like`、`unlike`。症状：提示"没找到主贴"，或取消喜欢没反应。

排查办法：把一份出问题的 JSON 和现象发给 Claude，让它对照当前页面结构调整脚本。

## 10. 仓库和备份建议

- `D:\GitLab` 下大概率是 git 仓库。视频会让仓库迅速膨胀，建议在 `.gitignore` 里排除 `*/media/` 和 `_raw/`，或者用 Git LFS。
- 要备份的话，`_raw` 是最小的"事实来源"，媒体文件可以再下载，但推文被删后就下不到了，所以媒体最好也备份。
- 脚本本身（`x-save-json.user.js`、`x_ingest.py`）也放进 `_tools\`，以后换电脑或重装浏览器时用。

## 11. 还没做的事

- **入库成功后才取消喜欢**：现在是点保存就取消喜欢。想做到"入库成功才取消"，需要让油猴脚本直接和本地程序通信，而不是靠下载文件夹中转。
- **关注名单**：用官方"下载数据存档"导入，每个作者一个 `people` 笔记，贴文用 `[[handle]]` 链接过去，Obsidian 的反向链接就是该作者的所有贴文。
- **存量喜欢**：同样用官方存档导入，不要批量爬取。
- **Quartz / Memos**：只有需要发布成网页或信息流浏览时再考虑，现在不需要。
