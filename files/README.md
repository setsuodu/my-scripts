# movedir.py

文件夹到文件夹的"剪切"工具（Windows / Linux / macOS，Python 3.8+，仅标准库，单文件）。

核心特点：**遇到超过目标文件系统长度限制的文件名/目录名时，自动缩短并继续移动，而不是跳过或报错。**

典型场景：把 Windows 上的文件夹移到 Unix 端（ext4 / eCryptfs / NAS / SMB 共享），中文文件名在 UTF-8 下占 3 字节，很容易超过 255（或 143）字节的限制。

---

## 命令行 API

```
python movedir.py SRC DST [--max-bytes N] [--dry-run] [--overwrite] [--log FILE]
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `SRC` | 必填 | 源目录。移动完成后，已清空的源目录会被删除。 |
| `DST` | 必填 | 目标目录，不存在会自动创建。不能位于 `SRC` 内部。 |
| `--max-bytes N` | `255` | 单个名字（文件名或目录名，不是整条路径）的 UTF-8 字节上限。eCryptfs 用 `143`。 |
| `--dry-run` | 关 | 只预览并写日志，不创建目录、不移动文件、不删除任何东西。 |
| `--overwrite` | 关 | 目标已存在同名文件时先删除再覆盖。默认是跳过。 |
| `--log FILE` | `movedir_log.csv` | CSV 日志路径（UTF-8 带 BOM，Excel 可直接打开）。 |

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 全部成功（允许有 `SKIP`） |
| `1` | 至少一个文件失败（见日志中的 `ERROR` 行） |
| `2` | 参数错误：源目录不存在，或目标位于源目录内部 |

### 示例

```bash
# 先预览
python movedir.py D:\data E:\backup --dry-run

# 正式移动
python movedir.py D:\data E:\backup

# 目标是 eCryptfs，上限 143 字节
python movedir.py D:\data \\nas\share\data --max-bytes 143

# 覆盖已有同名文件，并指定日志位置
python movedir.py D:\data E:\backup --overwrite --log D:\move.csv
```

### 输出

终端末尾打印汇总：

```
完成：移动 4（其中改名 3），跳过 0，失败 0。日志：movedir_log.csv
```

失败的文件会即时打印到 stderr：`[失败] <源路径>: <原因>`。

### 日志格式

CSV，四列：`status, source, target, note`

| status | 含义 |
|---|---|
| `OK` | 原名移动成功 |
| `RENAMED` | 名字被缩短后移动成功（`target` 列是新路径，用于回溯原名） |
| `SKIP` | 目标已存在同名文件，未移动（未加 `--overwrite`） |
| `ERROR` | 移动失败，`note` 列为异常信息；源文件保留不动 |

## 重命名逻辑

只在名字的 **UTF-8 字节数 > `--max-bytes`** 时触发；未超限的名字原样保留。文件名和路径中的**每一级目录名**都会独立检查。

`shorten(name, max_bytes)` 的步骤：

1. **判断**：`len(name.encode("utf-8")) <= max_bytes` → 原样返回。
2. **拆扩展名**：用 `os.path.splitext` 拆成 `stem` + `ext`。若扩展名本身超过 20 字节（异常情况），则视为没有扩展名，整个名字当作 `stem`。
3. **生成标签**：`tag = "~" + sha1(原完整名字)[:6]`，固定 7 字节（`~` + 6 位十六进制）。
4. **计算预算**：`budget = max_bytes - len(ext) - len(tag)`（字节）。
5. **按字节截断 stem**：取 `stem` 的 UTF-8 字节前 `budget` 个，再解码并**丢弃被切断的半个字符**，保证结果仍是合法 UTF-8。
6. **拼接**：`截断后的 stem + tag + ext`。

结果字节数始终 `<= max_bytes`。

### 例子（`--max-bytes 60`）

| 原名 | 字节数 | 新名 |
|---|---|---|
| `normal.txt` | 10 | `normal.txt`（不变） |
| `中`×40 + `.txt` | 124 | `中`×16 + `~73470b.txt`（59 字节） |
| `中`×41 + `.txt` | 127 | `中`×16 + `~c9f98f.txt`（59 字节） |
| 目录名 `长`×30 | 90 | `长`×17 + `~0fe01a`（58 字节） |

后两个文件截断后的前缀相同，但哈希取自**原完整名字**，所以不会互相覆盖。

### 注意

- **哈希只有 6 位十六进制（约 1677 万种）**：同一目录下两个不同的超长名恰好哈希相同的概率极低，但并非为零。一旦撞名，因默认不覆盖，后一个会被标记为 `SKIP`（"目标已存在"），不会丢数据。
- **同一个原名每次的结果相同**（哈希是确定性的），所以重复运行结果稳定。
- 目录被缩短后，其下的文件会放进缩短后的目录里（日志里 `target` 为完整新路径）。
- **只限制单个名字的长度，不限制整条路径**。Windows 侧通过 `\\?\` 前缀绕开 260 字符限制；若目标端整条路径超过 `PATH_MAX`（Linux 通常 4096），仍会失败并记为 `ERROR`。
- 只处理**字节长度**。目标端不接受的字符（如 `: * ? " < > |`）不会被替换。

## 移动逻辑

对每个文件：

1. 目标已存在且未加 `--overwrite` → 记 `SKIP`，跳过。
2. 先尝试 `os.rename`（同一磁盘/卷内，瞬间完成）。
3. rename 失败（如跨盘）→ `shutil.copy2` 复制（保留时间戳）→ 比较源与目标**文件大小** → 一致才删除源；不一致则删除目标并报错，源文件保留。
4. 任何异常只影响当前文件，记 `ERROR` 后继续处理下一个。
5. 全部处理完后，自底向上删除**已变空**的源目录（非空目录删不掉，会被保留）。

Windows 下所有路径会自动加 `\\?\`（UNC 路径用 `\\?\UNC\`）前缀以支持长路径。

## 限制

- 仅校验文件**大小**，不做内容哈希校验。
- 跨盘移动**不是原子操作**：复制中途中断，源文件仍在，但目标端可能留下不完整的文件。
- 不专门处理符号链接、文件权限、NTFS 备用数据流。
- `--dry-run` 不会检测目标端运行时才会出现的问题（权限、磁盘空间、非法字符等）。
